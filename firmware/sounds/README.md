# Robot sounds for the DFPlayer Mini

`sd/mp3/` holds the files for the robot's SD card. They are generated by `generate_sounds.py`,
which synthesizes every sound from tones and noise.

```
python3 firmware/sounds/generate_sounds.py
```

Needs Python 3 (standard library only) and ffmpeg. To change a sound, edit its function or its gain in the
`EFFECTS` table and regenerate; the output is deterministic, so only the edited sounds change.

## Format

MP3, mono, 44.1 kHz, 128 kbps CBR, with no ID3 tags and no Xing header (some DFPlayer clones stall on those).
Every sound is normalized to the same loudness and soft-limited below −1 dBFS, starts after 10 ms of silence, and
fades in and out over a few milliseconds so the speaker doesn't pop. The effects sit roughly between 500 Hz and
4 kHz, because a small speaker has almost no bass.

## SD card

1. Format the card as **FAT32** (cards of 32 GB or less work best).
2. Copy the `mp3` folder to the **root** of the card, so the files end up at `/mp3/0001.mp3`, ….
3. macOS writes hidden `._0001.mp3` files that confuse the DFPlayer. Remove them before ejecting:
   `dot_clean -m /Volumes/<CARD>`.
4. Play a file by its number with `DFRobotDFPlayerMini::playMp3Folder(n)`, e.g. `playMp3Folder(4)` for `0004.mp3`.

## Sounds

"Reaction" means the firmware can play the sound when the app sends that reaction; the others wait for
hardware or app events that don't exist yet.

| File | Name | When | Length |
| --- | --- | --- | --- |
| 0001 | boot | Power-on | 0.7 s |
| 0002 | connected | Reaction CONNECTED | 0.3 s |
| 0003 | disconnected | Phone disconnects or goes away | 0.5 s |
| 0004 | happy | Reaction HAPPY (correct answer) | 0.3 s |
| 0005 | encourage | Reaction ENCOURAGE (wrong answer): a soft "aww" with a hopeful lift, not a buzzer | 0.7 s |
| 0006 | celebrate | Reaction CELEBRATE (lesson complete) | 1.2 s |
| 0007 | hint | Reaction HINT: "aha!" | 0.5 s |
| 0008 | streak | Reaction STREAK | 1.2 s |
| 0009 | nod | Reaction NOD (match pair): a tiny tick, deliberately quiet | 0.1 s |
| 0010 | on_fire | Reaction ON_FIRE: an excited warble landing on a chime | 0.7 s |
| 0011 | sleep | Face falls asleep: a yawn | 1.2 s |
| 0012 | wake | Face wakes up | 0.5 s |
| 0013 | giggle | Touch pad: a pat on the head | 0.5 s |
| 0014 | purr | Touch pad: long press | 1.1 s |
| 0015 | pickup | Accelerometer: picked up ("whee!") | 0.5 s |
| 0016 | shake | Accelerometer: shaken (dizzy) | 1.0 s |
| 0017 | knocked_over | Accelerometer: tipped over ("oof", then dizzy) | 0.9 s |
| 0018 | reviews_due | App: reviews are due | 1.0 s |
| 0019 | streak_risk | App: the streak ends today without a lesson | 1.2 s |
| 0020 | curious | Idle: an occasional "hm?" | 0.3 s |
| 0021 | uh_oh | Something failed, e.g. an unknown command | 0.4 s |

LISTENING and THINKING have no sound on purpose: during LISTENING the phone is speaking, and THINKING is
the resting state during a question.
